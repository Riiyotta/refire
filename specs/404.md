# NotFound page (Next.js default `_error`, inside the Refire app shell)

Reference screenshots: `reference/pages/404-desktop-1440-fullpage.png`, `reference/pages/404-mobile-390-fullpage.png`.
Document title: `404: This page could not be found`. The page is one viewport tall and does not scroll (docH = viewport height at 1440×900 and at 390×844).

## Structure (DOM order)
1. Header: **same as home Header** (see ROUTES.md for geometry).
2. CookiePane: **same as home**.
3. Error body (below).
4. Preloader: **same as home**. It shows on first paint ("0%", "++", "1.00784", "1.00811", "initializing...") and is then removed from the DOM.
5. CustomCursor: **same as home**.

## Page shell
- `body`: `position: fixed; inset: 0; display: flex; flex-direction: column; min-height: 100vh`. Background #fff, color #000. These values come from the site's global CSS plus the error page's inline `<style>`. Base font `SuisseIntl, Arial, Helvetica, sans-serif` 12px/15px.
- `#__next`: block, full viewport.

## Quirk: header is invisible on this page
The header is the same component as on home: color rgb(254,254,254) with `mix-blend-mode: difference`. On the 404 there is no dark media behind it, and the blend does not invert against the white body (the fixed-body stacking context). It renders near-white on white. A device-scale element screenshot shows the logo as a barely visible light-grey ghost, and the clock and CONTACT pill are effectively invisible. All header elements have computed opacity 1 and `SplitTextAnimate` letters at `translate(0,0)`, so this is a rendering result, not a hidden state. For a faithful clone, use the shared header unchanged. If the blend works in the rebuild (header turns black), that is a deviation the user may actually prefer.
